# Bitacora 2026-10-12 — Timeouts masivos: causa raiz + fix

## Causa raiz (doc oficial opencode.ai/docs/mcp-servers, vigente hoy)
- El `timeout` default para traer tools es **5000 ms**. 9 arranques en frio simultaneos (node x4, python x2, exe x3)
  en Windows con Defender no entran en 5s -> `mcp connect failed: Request timed out` en todos salvo el .exe nativo mas rapido.
- El error `id:0` de playwright era el mismo sintoma visto desde otro angulo: respuesta tardia sin request pendiente.
- Los binarios estaban sanos (handshakes manuales OK); el shim .ps1 igual se reemplazo por node directo (menos overhead de arranque).

## Fix
- `"timeout": 120000` en las 10 entradas MCP de `opencode.json` (opcion documentada oficialmente; si v1 la ignora, es inocua).
- Sentry: entrada local eliminada (binario 0.41 colgado + 0.42 regresion) -> remota oficial `https://mcp.sentry.dev/mcp` con `oauth: {}`.
  Requiere que el usuario ejecute `opencode mcp auth sentry` (flujo browser) una vez.

## Pendiente del usuario
1. Reload OpenCode (cargar nueva config).
2. `opencode mcp auth sentry` en terminal para activar Sentry.
3. Verificar en log `mcp connected` x10.
